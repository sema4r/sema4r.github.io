Even the explicit code below does not guarantee that the compiler (nvcc + ptxas) will always emit 'ld.shared.v4.b32' (or 'ld.global.v4.b32' for global memory) i.e. a vectorized 128-bit load. 

<img src="/assets/images/VECT128/code-preview (2).png"
     alt=""
     class="post-image">
     
```cpp
__shared__ __align__(16) int smem[4];
int4* __restrict__ __align__(16) ptr = reinterpret_cast<int4*>(smem);
int4 x = ptr[0];
```

Possible reasons are :

(1) Optimization level too low. Vectorization might not happen for levels < O3 .

(2) Register pressure too high. If the compiler is low on registers it might emit scalar loads for a more flexible schedule.

Alignment knowledge, aliasing information can be additional reasons in other cases. 

Philosophy : CUDA C++ expresses intent, but ptxas chooses the final instructions. 

That's why performance-critical libraries like CUTLASS/cuBLASLt or TensorRT use inline PTX for vector loads.

Code looks like this :

<img src="/assets/images/VECT128/code-preview (1).png"
     alt=""
     class="post-image">

```cpp
__shared__ __align__(16) int smem[4];
int* ptr = smem;

int x0, x1, x2, x3;

asm volatile(
    "ld.shared.v4.b32 {%0, %1, %2, %3}, [%4];\n"
    : "=r"(x0), "=r"(x1), "=r"(x2), "=r"(x3)
    : "=r"(ptr) 
);
```
